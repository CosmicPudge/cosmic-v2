# Cosmic Web Push foundation

Phase 5B adds Web Push as a delivery channel for deterministic Sports signals. The browser-local Cosmic notification center remains local and is not migrated here.

`push_subscriptions.endpoint` is globally unique. Registering the same browser subscription while another account owns it rebinds that endpoint to the currently authenticated account, which prevents the previous account from receiving future pushes on that browser. One account may still own multiple endpoints/devices.

`push_deliveries` is keyed by the deterministic Sports signal ID and subscription ID. The minimal title/body/route payload is retained so a future bounded retry can recover after a worker crash without refetching provider data. Retries update the existing delivery record instead of inserting another row. A 404 or 410 from the Web Push provider expires the subscription; other failures are recorded as temporary failures and are not retried in a tight loop.

Required server-only configuration is `WEB_PUSH_VAPID_PUBLIC_KEY`, `WEB_PUSH_VAPID_PRIVATE_KEY`, and `WEB_PUSH_SUBJECT`. No production keys are generated by this repository change.

Migration `0048_add_web_push_delivery.sql` is intentionally prepared but must be applied separately. `runSportsPushCycle()` and its protected internal route are prepared, but Vercel Cron is not configured. The runner begins with accounts that have active push subscriptions, shares snapshots for identical favorite sets, establishes cold-start checkpoints, and evaluates the existing signal engine. It remains unavailable until 0048, VAPID, and production scheduling are configured.
